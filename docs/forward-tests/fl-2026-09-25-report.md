## The technical failure

- **Cause.** Between the driver's start check at 06:37 and the first signal at 10:07 the montage
  window lost its `montage1` name. Same DAS process, same three windows; the name is simply
  gone. How it was lost is not known; nothing in the DAS log between 06:37 and 10:07 is a
  desktop or window event.
- **Why it was silent.** The driver checked the name once at start, and `script()` returns the
  socket reply but the driver never read it, so `does not exist` was thrown away 15 times while
  each `inject` event was logged as if it had happened.
- **Fix (this commit).** `inject()` now raises when the reply names a missing window or when no
  `FL` log line follows the injection. The driver halts new entries, speaks an alert through the
  LifeOS notifier, and the flatten path reports the same failure instead of pretending.
- **Restoring the name over the API did not work this time.** `GetWindowObj()` with no argument
  returned a generic `WindowObject` with no symbol, not the montage. The name has to be set by
  hand on the montage title bar, and then File → Save Desktop.

## Improvements to carry forward

1. **Stop width** is still the dominant loss mechanism (11 of 18 stops across both days inside
   two minutes). A floor of 0.5% of price, or ATR on 5-minute bars, before the next test.
2. **Long-only / short-only per name** from the gameplan, so a runner is never shorted.
3. **Do not open a position that cannot reach its stop before the session end.** Signals inside
   the last 15 minutes of the window should be suppressed, not taken into the flatten.
4. **Name persistence.** Verify the target on every injection (done) and record in WISDOM how
   the montage lost its name once that is understood.
5. **Notion page for each results file** so these are referenceable; connector authentication
   pending.
